- A03のif関連：elseの省略、片側のみの代入、各側で異なる変数への代入、

## 比較器の制御

| Cの条件 | MLIRのpredicate | 既存の制御コード | 比較器へ渡す入力 |
|---|---|---|---|
| a == b | eq | BR_BEQ | a, b |
| a != b | ne | BR_BNE | a, b |
| a < b | slt | BR_BLT | a, b |
| a <= b | sle | BR_BGE | b, a |
| a > b | sgt | BR_BLT | b, a |
| a >= b | sge | BR_BGE | a, b |

`a <= b`は`b >= a`として扱う。`b+1`などへの置き換えはしないため、
INT_MIN/INT_MAXで余分なオーバーフローを起こさない。

比較器のレイテンシはoperators/cmp.pyから取得する（既定1）。
最後のサイクルに比較器出力をFSMの`io.dp_cmp_out`へ与え、
その末尾のエッジで選択した枝へ遷移する暫定モデルとした。
入力と比較コードは完了まで保持する。同じブロックの他の演算も完了してから分岐する。
この最終サイクルの比較結果をFSMが参照できることは、RTL統合時に照合が必要。

比較結果をGPRへ直接書くポートは仮定しない。
`int x = a < b;`や`return a == b;`は、小さなifへ変換して1か0を選び、
各枝でALUのコピーを使って合流結果用のレジスタへ書く。

## フロントエンドと合流

`Int32MLIRGen`は既存のC→MLIR生成器を継承し、int32のif・比較・スコープを担当する。
両側を独立した変数環境で生成し、どちらかで更新された外側の変数をscf.ifの結果とする。
更新されなかった側では分岐前の値を渡す。ブロック内で宣言した同名変数は、
ブロック終了時に外側の変数へ影響させず破棄する。

`mlir_to_cdfg/structured.py`がscf.ifをthen/else/joinのCFGへ変換する。
合流する値ごとに、各枝の末尾にコピーを置き、共通のレジスタへ割り当てる。
コピー結果と合流値の生存区間はまとめて扱う。区間が重なる別の値は同じレジスタを使わない。
検証器は依存時刻に加え、値の定義が使用箇所へ至る全経路上にあること、
各合流辺に必要なコピーがあることを確認する。

`code_gen/int32.py`は条件別のFSM遷移を生成する。
比較コードと入力交換は、現在は既存の`code_gen/emitter.py`の共通処理を利用する。
実行モデルもプログラムカウンタを分岐先へ進め、両方の枝を順番に実行しない。
直線計算は従来のv1制御列、分岐を含む制御列はv2とし、旧モデルによる誤解釈を避ける。

## 比較処理の共通化

比較の修正を今後の経路でも利用できるよう、既存ファイルに次の処理を集約した。
新規ファイルは追加していない。

- `mlir_to_cdfg/core.py`の`integer_comparison_predicate`：MLIRの整数比較条件を読み出す。
  通常の変換と`structured.py`の構造化CFG変換が共通利用する。
  旧経路の`scf.for`から生成する比較にも、上限未満を表す`slt`を明記する。
- `code_gen/emitter.py`の`lower_integer_comparison`と`CMP_CODES`：
  6種類の符号付き比較を、比較器の演算・制御コード・入力順序へ変換する。
  旧経路の`BR_BLT`固定を解消し、`code_gen/int32.py`もこの処理を呼び出す。
  `<=`と`>`は入力を交換する。元のグラフの入力順序は変更しない。

比較条件の欠落、不正な条件、符号なし比較、浮動小数点比較、i32以外の比較は
推測で制御コードを生成せず、明示的にエラーとする。

`tests/test_branches.py`へ回帰テスト3件を追加した。
両変換経路での6種類の条件保持、旧経路の制御コードとレジスタ・即値の入力交換、
未対応条件の拒否を確認する。共通化の修正時点では、スコープ修正を含め計32件。
共通化後、WindowsのPython 3.12.14とWSLの既存Python 3.14.4で32件すべてが合格した。
旧経路全体の分岐・ループの実行結果やRTL動作を保証する検証ではない。

## 途中のreturnと共通終了ブロック

A04・A05に関わる制御フローを、既定のint32経路で拡張した。
従来は関数末尾のreturnを1つだけ認めており、次の例は入力検査で拒否されていた。

```c
int f(int a) {
    int x;
    if (a < 0) return -a;
    else x = a + 1;
    return x;
}
```

修正後は、負数なら`-a`、それ以外なら`a+1`を返す。
前者は`x`を読む文へ到達しないため、後者だけで`x`が初期化されていればよい。
if/elseの両側でreturnする関数、入れ子のreturn、ブロック内のreturnにも対応する。

### 変換と終了の仕組み

- 既存の`c_to_mlir/core.py`の`_gen_returning_sequence`で、returnを含む文列を
  1つの戻り値に変換する。returnを見つけた経路では後続の文を生成しない。
  returnを含むifでは、後続の処理を継続できる枝に配置し、各枝の最終戻り値を
  `scf.yield`で合流させる。分岐領域内に`func.return`を直接置かない。
- `c_to_mlir/int32.py`は、この変換の呼び出しと到達性・初期化の検査を変更した。
  合流後の初期化状態は、returnせず合流へ到達する枝だけから決める。
  既存の宣言ごとの識別子を使うため、同名の内側変数とも混同しない。
- MLIR上の`func.return`は最後の1つにまとめる。既存の構造化CFG変換・値コピー・
  レジスタ割り当てを使い、共通終了ブロックでSRAMへ戻り値を1回書き込む。
  書き込み完了の次サイクルをdoneとする既存仕様は変更しない。

新規ファイルは追加せず、終了処理・スケジューラ・実行モデルの`int32.py`も変更していない。

### 判定基準と制限

`tests/test_branches.py`に6件を追加し、テスト総数は38件になった。
途中・両側・入れ子のreturn、スコープ、継続経路だけの初期化判定、戻り値不足の拒否、
return後の計算の非実行を確認する。演算レイテンシ1/2/4で単一の戻り値書き込みと終了を確認し、
固定seedの15プログラム×5入力を独立したPythonの期待値と比較する。
制御フローが非巡回で、全ブロックが入口から到達でき、出口が1つであることも検査する。
WindowsのPython 3.12.14とWSLの既存Python 3.14.4で38件すべてが合格した。

すべての分岐経路でint値を返すことを要求する。条件の定数評価は行わないので、
`if(1)return 7;`だけの関数も、elseまたは後続のreturnがなければ拒否する。
到達不能な文も入力の構文・型・変数の検査対象だが、実行コードは生成しない。
後続の処理を複数の枝へ配置するため、途中のreturnが複雑に入れ子になるとコードや
状態数が増える場合がある。共通化によるサイズ最適化は今後の課題とする。
このreturn修正時点の対応範囲はループのないint32経路であった。
ループ内のreturnは次節で対応する。legacy経路全体、Scalaビルド・RTLシミュレーションの検証は含まない。

## A11とwhile・forへの対応

### 問題と変更

これまではwhile/forを入力検査で拒否し、スケジューラも非巡回のCFGだけを扱っていた。
さらに、状態番号の大小だけでレジスタの生存区間を決めると、ループ先頭へ戻った後も
必要な値を「使用済み」と判断して上書きするおそれがある。A11に関わるこの制約を修正した。

| 既存ファイル | 役割 |
| --- | --- |
| `c_to_mlir/core.py` | `CFGMLIRGen`がループを含む関数を明示的なMLIRの`cf.br`・`cf.cond_br`へ変換する。ブロック引数で変数を渡す。 |
| `c_to_mlir/int32.py` | ループの入力検査と生成器の選択。ループ本体は0回実行の場合があるため、本体だけで行った初期化をループ後に保証しない。 |
| `mlir_to_cdfg/core.py`・`structured.py` | cf方言を読み込み、基本ブロック・分岐・後退辺・値のコピーへ変換する。コピー元をすべて一時値に退避してからコピー先を更新する。 |
| `state_assign/core.py` | 基本ブロックごとに既存ASAPを適用して状態を配置する。ブロック間は状態番号の時間差で判断せず、CFGと支配関係を検査する。 |
| `register_allocate/allocator.py` | 後退辺を含め、生存する値が変わらなくなるまで解析を反復する。入力を保持する期間と出力の予約期間も含めて干渉を判定し、レジスタを割り当てる。 |
| `state_assign/int32.py` | 上記処理への振り分けと、循環CFGを含む検証の接続。 |

コード生成器と実行モデルは、既存の分岐先指定をそのまま利用する。
反復回数ぶんの展開はせず、生成した状態へ戻って繰り返す。
レジスタの生存解析の反復回数と、Cプログラム実行時の反復回数は別物である。
新しいファイルは追加していない。ループのない関数は既存の変換経路を使う。

### 対応する動作

- `while`は本体に入る前に条件を検査し、各反復で評価し直す。
- `for`は初期化を1回実行し、条件・本体・更新を繰り返す。減少方向や2以上の増分、
  初期化・条件・更新の省略、複数の初期化宣言・更新文も扱う。
- 文としての`++`・`--`、ループの入れ子、分岐との組み合わせを扱う。
  `for(int i=...)`のiはループ外へ漏れず、外側の同名変数と区別する。
- ループ内のreturnは共通出口へ進む。forの更新や残りの本体を実行しない。
  戻り値のSRAM書き込みは1回で、既存の完了タイミングを保つ。

### 検証と制限

既存の`tests/test_branches.py`に9件を追加し、総数は47件。
0回・1回・複数回、条件値の更新、入れ子、スコープ、途中のreturn、変数の入れ替え、
ループ中も使う値の保持、比較結果の0/1化、レイテンシ1/2/4を確認する。
固定seedの12プログラム×5入力をPythonの期待値と比較する。
不正な後退辺のコピー・レジスタ競合・分岐先・レジスタ不足の拒否も確認する。
WindowsとWSLで47件すべてが合格した。既存の`input/test_for.c`も実行し、
引数0で戻り値0、引数5で戻り値10を確認した。

`break`・`continue`・`do while`、式の値としての`i++`などは未対応。
無限ループの停止性は証明しない。入力検査ではループが0回でも戻り値があることを
要求するため、`for(;;){return 1;}`にも後続のreturnが必要となる。
実行モデルの既定上限100,000サイクル超過はエラーとし、誤って完了扱いしない。
上限は`model.run(..., max_cycles=...)`で指定できるが、ハードウェアには生成しない。
コピーの削減、ループのパイプライン化、スピルによるレジスタ不足解消は今回行わない。
Scalaビルド・RTLシミュレーションは未実施であり、legacy経路全体の修正でもない。

## A09の完了時刻検査とA21の回帰テスト

直線計算、if/else、途中のreturn、ループの各段階に同じ完了条件を適用する。
既存の検査に対して、doneの余分な遅延、戻り値STOREの識別情報の取り違え、
無条件遷移時の未完了演算、doneからの分岐を注入したところ、修正前は14の
テストケースで異常を見逃した。今回追加した検査でこれらを拒否する。

### A09：何を、どこで検査するか

演算の開始状態を`s`、レイテンシを`L`とすると、書き戻しは`s+L-1`の末尾、
依存する演算の開始は`s+L`以降とする。既存の演算器定義は変更していない。

| 段階 | 検査内容 | 実装 |
| --- | --- | --- |
| スケジューリング・割り当て後 | 時刻とレイテンシの妥当性、演算の所属ブロック、ブロック範囲の重複、ブロック退出前の全演算完了、同一ブロック内の入力値の準備完了 | 既存`state_assign/core.py`の`verify_completion` |
| コード生成前 | 上記検査を再実行し、壊れたスケジュールから制御列を生成しない | 既存の`build_image`→`verify_schedule`呼び出しを利用 |
| 終了時刻 | 戻り値STOREが識別された1つだけで、共通出口に属し、その完了直後がdoneであること | `verify_completion` |
| 実行モデル | 入力保持・書き戻しの時刻、条件付き／無条件遷移時に未完了演算がないこと、STORE完了の次の実行サイクルがdoneであること | 既存`model.py` |

入力値の準備完了はグラフのデータ辺だけでなく、SSAの定義とオペランドからも
再構築して検査する。データ辺を誤って失った場合も、同一ブロック内で早すぎる
入力値の使用を見逃さない。ブロック間は既存の支配関係と出口の完了検査を併用する。
ループの状態番号は時刻ではないため、状態番号の大小を反復間の時刻比較には使わない。
実行モデルもSTOREを行った実際のステップ数を記録してdoneを検査する。
