# A03：同名変数の宣言前の代入を保持する

## 再現した問題

```c
int f() {
    int x = 1;
    {
        x = 2;
        int x = 3;
    }
    return x;
}
```

正しい戻り値は2だが、修正前のint32経路では1になった。
外側を`int x;`に変えた例では、代入済みなのに未初期化として拒否された。
ブロック入口の値・初期化状態を復元していたことが原因。

## 修正

`passes/c_to_mlir/int32.py`の`_prepare_source()`で名前解決と検査を共通化した。

- 引数と各ローカル宣言へ一意な内部識別子を付ける。
- スコープのスタックは「ソース上の名前 → 宣言識別子」を保持する。
- 宣言に到達するまでは外側の識別子を参照し、到達後は内側の識別子を参照する。
- 初期化状態は識別子ごとに保持する。ブロック終了時は内側の識別子だけを除く。
- 新しく解析したASTの宣言・参照名を内部識別子へ置き換え、MLIR生成でも同じ区別を使う。
  入力Cファイルは書き換えない。ABIに表示する引数名は元の名前を保持する。
- MLIR生成時も、ブロック終了時に外側の最新のSSA値を維持し、入口の値へ巻き戻さない。

`int x = x;`は新しいx自身の未初期化読み取りとして引き続き拒否する。
同一スコープでの再宣言、片方の分岐でしか初期化されない変数の読み取りも拒否する。
旧legacy経路、ループ、途中のreturnには今回変更を加えていない。
